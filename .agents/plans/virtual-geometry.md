## 1. Crate layout (all in the Helio submodule; "components live in helio", core has zero VG knowledge)

```
helio/crates/
  helio-vg-format      cluster/page/DAG on-disk + GPU structs, bit packing, constants (no deps on wgpu)
  helio-vg-build       offline+runtime DAG builder (cluster, group, simplify, page) — pure CPU, rayon
  helio-vg-stream      page residency, request readback decode, upload scheduler (uses pulsar_scenedb::Residency)
helio/crates/passes/3d/
  helio-pass-vg-cull        instance BVH traversal + cluster DAG cut + two-phase occlusion + binning
  helio-pass-vg-raster      Tier 1 HW raster (visbuffer) + Tier 2 SW micro-raster + tile classify
  helio-pass-vg-dense       Tier 3: tiled depth-peel fallback and (later) ray-query path
  helio-pass-vg-shade       vis resolve + material/attribute eval -> G-buffer + depth
  helio-pass-vg-bvh         GCBVH build/refit (Morton LBVH over instances; asset cluster BVHs are baked)
helio/crates/helio-component/src/components/virtual_geometry_component.rs   (per-instance overrides)
```

Dependency rule: `helio-vg-format` ← everything. `helio-vg-build` ← `helio-component` (mesh load/cook), never ← passes. Passes depend on `helio-core`, `pulsar_scenedb` (keys/handles only), `helio-pass-gbuffer` (G-buffer targets). `helio-core` and `helio-default-passes`' only knowledge is "add these passes"; the passes find their inputs by `BufferKey` (mirrors `AuthoredLodSelection` / scene-join style).

## 2. Data formats and asset pipeline

### 2.1 Cluster DAG (offline / import-time, cached; runtime fallback builds in a background job)
1. **Cluster** the mesh: ≤128 tris (target 96–128, min 32 for leftovers), ≤128 verts per cluster, locality + cone aware (meshopt `buildMeshlets` style scoring). Leaf level = cluster set of the full-res mesh.
2. **Group**: partition adjacent clusters (4–8 per group) by shared-edge graph, minimizing boundary edges. In-house greedy+refine partitioner (Morton seed + FM refinement) to avoid a C `metis` dependency; metis becomes an optional feature if quality demands it (decision D4).
3. **Simplify the group** to ~½ triangles with **locked group-boundary vertices** (so neighbouring groups stay crack-free), QEM-based (`meshopt_simplify` with lock flags or equivalent), producing monotonic object-space `error`; **parent error ≥ max(child errors)** enforced, plus sphere-bounds containing the children's bounding spheres (bounds monotone) — this is what makes a per-cluster independent decision give a consistent cut.
4. **Split** the simplified group back into ≥2 parent clusters; repeat until one root group remains (one or two clusters).
5. Each cluster stores *two* error spheres: its own `self_error/self_sphere` and its group's `parent_error/parent_sphere`. Runtime cut rule (identical per cluster, no neighbour communication):
   `render(cluster) = project_err(self) <= τ  &&  project_err(parent) > τ`.
6. Attributes: normals/uv/tangent preserved via attribute-weighted QEM with seam-aware edges; UV/hard-edge seams are *locked like boundaries* for the first implementation (safe, costs some reduction depth; revisit).
7. Material sections (`MeshSection`): clusters never span a material section (cluster is built per section). `material_slot` stored per cluster.

### 2.2 Streamable GPU layout
- **Page** = 128 KiB, a self-contained set of clusters of **one or more groups from the same DAG depth band** (so coarse LODs cluster into root pages). Header: cluster count, offsets. Per cluster record (**64 B**): bounds sphere (16), cone axis+cutoff (snorm8×4 + 1), self_error + parent_error (f16×2), self/parent-sphere indices into a page-local table, tri count/vert count (u8), material slot (u16), vertex & index data offsets, `group_id`, flags (e.g. `has_children_resident`).
- **Vertex data**: local (≤128) indices as u8 triplets; positions **quantized** (page-local anchor + per-cluster bit-width, 10–16 bits/axis) with oct-normals u32 and uv f16×2 (+uv1 on request) in a separate *attribute stream* read only by the shade pass. Position stream is what raster tiers touch (bandwidth-minimal).
- **Hierarchy (per asset)**: a baked BVH over *cluster groups*, 4-wide nodes (child bounds + `max_parent_error` + page id), stored in a *hierarchy buffer* that is **always resident** (small: ~1-2 B/tri). Root pages (coarsest cut) always resident → holes are impossible; streaming only adds detail.
- Content id = existing mesh content id (xxh3-128 of the source geometry) + builder format version. Native `.mesh` v4 stores an optional length-delimited `.vgeo` chunk after the unchanged classic geometry and section/material metadata. When the chunk is absent or stale, `VirtualGeometryComponent` builds it in the background and atomically rewrites the native asset; the active scene renders classically until the root pages are resident, then VG suppresses the classic main-view draw. Reimport replaces the asset from source and drops the derived chunk for regeneration.

### 2.3 Memory relationship to the SceneDB pools
SceneDB's interned vertex/index pool keeps serving the classic path and BLAS builds. Cluster pages are an **additional representation** owned by `helio-vg-stream`'s `Residency<VgPage>`.

**Current v1 runtime constraint:** classic geometry stays GPU-leased for VG meshes. A static-mesh instance carries no content id on the GPU, only its interned classic vertex range, and the scene join drops instances with an empty classic range; the range is therefore the identity `vg_asset_ready` is keyed by (`VgRuntime::request_asset(content, vertex_offset, vertex_count, ..)`). Shadow casting also uses it as the current proxy. The native file preserves classic data as a fallback independently of this GPU residency constraint. Thus v1 reduces main-view draw work but does not yet eliminate classic GPU memory; decoupling asset identity and shadow proxies is a follow-up.

## 3. SceneDB integration (no new owner, generic patterns preserved)

1. **Per-instance data**: VG reads the *existing* `static_objects` / `materials` rows (published by the scene join) for transform, bounds, mesh identity and material. The scene join's `MeshInstance` output already carries per-section rows; we add **one `u32` "vg_instance_flags + asset slot" lookup** via a new, optional join output `vg_instances` produced by a *VG-owned `SceneDerivation`* (same mechanism as `SceneJoin`/`AuthoredLodSelection`), not by editing `helio-core`. It joins `StaticMeshComponent` row ↔ `VirtualGeometryComponent` row (optional) ↔ asset cluster handle, on GPU.
2. **`VirtualGeometryComponent`** (helio-component, `#[engine_class(... scene_store)]`, `#[register_world_component]`, same pattern as `LODComponent`): reflected `#[property]` fields + `#[gpu(buffer = "vg_instance_overrides")]` row: `enabled`, `tier_lock` (Auto/HwRaster/SwRaster/Dense), `lod_error_scale`, `force_root_only`, `shadow_caster`. A mesh with **no** component uses the global defaults, so existing scenes work untouched. Being its own component-instance entity it needs no change to `ComponentOwner`/`ComponentMeta` handling.
3. **Change flow**: the derivation uses SceneDB `flushed_rows` / `content_signature` (same as the foliage/LOD passes) to refit/rebuild only on change; static rows are never re-uploaded each frame (aligns with the Movability plan in `docs/render-movability-audit.md`: `Static` ⇒ BVH leaf never refit; `can_deform` irrelevant — VG meshes are rigid).
4. **GCBVH is execution data** owned by `helio-pass-vg-bvh` (like join outputs): rebuilt/refit from the instance rows, **no CPU copy of the scene**, no `World::query` in render code. A ledger row per new component / buffer / pass is added to `scene_inventory/ledger.toml` (the architecture test requires it).
5. **Global mode switch**: not a scene component; a `VirtualGeometrySettings` resource in `pulsar_settings` (Auto / ForceNonRtFallback / ForceHwRaster / Off + τ pixel error + budget MB), pushed to the passes via `RendererConfig`-style runtime setter. Editor UI is a small Settings entry.
7. **LOD precedence.** An instance is *VG-active* iff VG is globally on, its `VirtualGeometryComponent` (if any) is `enabled`, and its mesh's `.vgeo` is resident (root page + hierarchy). For a VG-active instance the authored-LOD selection must not run: the authored-LOD derivation (`engine_backend::scene::authored_lod*`) skips rows flagged VG-active via a generic per-row `lod_suppressed` flag in a buffer published under a `BufferKey` by the VG derivation (neither side knows the other's types). If VG is enabled but not ready (asset not cooked, feature fallback), the instance is *not* VG-active and the authored LOD applies as before, so no frame ever has neither. `LODComponent` stays attached and reflected; it is only inert while VG-active (inspector note).
6. **Ledger / Memory / LOD docs** updated: `.agents/VIRTUAL_GEOMETRY.md` (as built), `.agents/LOD.md` cross-reference, `.agents/MEMORY.md` page budget.

## 4. GCBVH and instance-agnostic culling

**Structure — two-level, one traversal.** (a) *Asset cluster-group BVH* (baked, §2.2) in asset space; (b) *Global instance BVH* (built by `helio-pass-vg-bvh`) over instance world-AABBs using GPU LBVH (Morton sort via the existing radix-sort kernels in object-batch, Karras tree, refit bottom-up). Leaves of (b) are instances; tiny, densely packed instances are merged by the builder into **batch leaves** (≤64 instances sharing a cell) so multi-mesh "city block" scenes don't pay one BVH node per bolt. Traversal descends (b) then continues into the instance's (a) *without per-instance cluster lists*: a single persistent-threads job queue holds `{node, instance}` pairs, so one giant asset and 100k small ones are the same code path.

**Per-job tests** (compute, instance-agnostic = no per-instance dispatch or per-instance cluster arrays):
1. Frustum (instance transform applied to the node bounds), layer/visibility flags.
2. **Hi-Z occlusion**, two-phase (Nanite style): phase 1 against the previous frame's Hi-Z with last frame's visible set drawn first; build Hi-Z from that; phase 2 re-tests what phase 1 culled/was unknown against the new Hi-Z and draws the rest. Reuses `helio-pass-hiz` kernels.
3. **Screen-space error**: `project(error*lod_error_scale*instance_scale, dist) <= τ_px` (default 1 px, per-instance scale from `VirtualGeometryComponent`), using the cut rule from §2.1.5. Conservative bound uses the sphere's closest point to the camera.
4. **Cone (backface) cull** on the cluster level (disabled for non-angle-preserving / mirrored instances; derive flags in the derivation, not per cluster).
5. **Page residency**: if the needed child page is not resident, draw the resident parent and append a page request (deduplicated by atomic bitset per page). Never draw "nothing".

**Outputs**: visible-cluster list `{instance_id, cluster_slot}` partitioned into **bins** by (tier, triangle-count class): `HW_small_tris? / HW / SW / dense-candidate`. The tier decision is per *cluster*: projected edge length of the cluster's average triangle (from bounds + tri count) `> 2 px` ⇒ HW; `≤ 2 px` ⇒ SW; per-tile overlap estimate (§5.3) can promote SW clusters to Dense. `tier_lock` overrides apply here.

## 5. Three-tier pipeline

### 5.0 Vis buffer and the 64-bit payload (needs your sign-off, D1)
The spec's payload `ClusterID + TriangleIndex + Barycentrics` (64 bit) cannot share one atomic word with depth. Plan:
- **Raster-time key** (what tiers write/race on): `depth32 (reversed-Z float bits) : id32`, id32 = `visible_cluster_index (25 bit) | triangle (7 bit)`.
- **Resolved unified payload** (RG32Uint, what shading and tools read): `R = id32`, `G = bary_u16 | bary_v16`. A cheap `vis_resolve` compute pass recomputes **exact perspective-correct barycentrics** per pixel from the three decoded vertex positions and the pixel ray (no dependence on `@builtin(barycentric)`), and Tier-3-RT writes the hardware barycentrics directly. All tiers therefore produce the same payload, as required; the raster hot loops stay 64-bit/2×32-bit friendly.

### 5.1 Tier 1 — macro geometry, hardware raster
No mesh shaders in wgpu 30 → **vertex pulling** via `draw_indirect` with `first_instance` (already a required feature): instance = visible cluster, vertices = `3 × tri_count` of the bin (bins by tri count 32/64/96/128 to limit degenerate waste; 4 draws, no MDI-count needed; `MULTI_DRAW_INDIRECT_COUNT` is an optimisation, not a dependency). Vertex shader decodes quantized positions + instance transform; fragment shader writes `id32` to an `R32Uint` color target with the shared `Depth32Float` (reversed-Z) depth test/write, and `@interpolate(flat)` triangle id; no material evaluation ⇒ zero overdraw shading cost. Conservative raster not needed.

### 5.2 Tier 2 — sub-pixel micro-polygon compute raster
One workgroup per SW cluster (or per cluster chunk), 1 thread per vertex transform (to shared memory), then 1 thread per triangle: bbox ≤ ~32 px; tiny tris use a point/line-like path (≤1 px) with coverage by pixel-center test, larger ones edge-function scan; **64-bit `atomicMax` on `depth<<32|id`** into a storage buffer (`SHADER_INT64_ATOMIC_MIN_MAX`; new optional device feature in `config.rs`). Reads the HW depth to early-reject. Merge step (in `vis_resolve`) picks the nearer of HW and SW per pixel.
**Without int64 atomics:** Tier 2 degrades to the tile-binned path of §5.4 (same kernel family), so the feature is an optimisation not a requirement.

### 5.3 Overlap detection
Tile (16×16) counters are fed by the SW raster: `atomicAdd(tile_tri_count)` for bin-overlap and `atomicAdd(tile_contention)` when an atomicMax loses/replaces. A `tile_classify` pass compares to thresholds ⇒ marks the tile **dense**. Dense tiles are re-processed by Tier 3 (their SW/HW results discarded for that tile) — and since that is known one frame late in the general case, the previous frame's dense mask is used for *routing this frame's* clusters (with a conservative same-frame fix-up pass), avoiding a pipeline stall.

### 5.4 Tier 3 — ultra-dense overlap
- **3-NonRT (baseline, built first, runs everywhere):** tile-based depth-peeling compute raster. Per dense tile: bin triangles from the tile's cluster list into shared memory (workgroup bucket sort by 12-bit quantized depth, 4096-entry key array + radix/bitonic in shared mem), peel front-to-back in K ≤ 4 layers/passes bounded by `8-16 KiB` shared memory, writing the nearest surviving fragment per pixel; overflow ⇒ falls back to more peels (bounded, then clamp + `overflow` counter surfaced in the debug UI). Works on Metal/DX12/Vulkan/GL-class compute; no int64.
- **3-RT (later phase, gated):** primary rays over dense tiles via `wgpu_ray_query` against a **TLAS of instance proxies + BLAS built from a streamed proxy LOD** (hardware RT cannot do per-pixel DAG cuts, so rays hit a proxy LOD chosen so its error ≤ τ for tile's closest distance; pixel exactness within τ). Cost O(pixels). Gated by `EXPERIMENTAL_RAY_QUERY` (+ the existing compiler-crash filter in `config.rs`). **Risk: BLAS build cost/memory for proxy LODs and wgpu RT instability** (see risks) — a custom compute GCBVH traversal is the alternative if it fails.

### 5.5 Deferred shading (single compute pass)
1. `vis_resolve`: merge HW/SW/dense results, compute barycentrics ⇒ unified payload + final depth.
2. **Material binning**: count pixels per material class (existing `material_class` from scene-join sections), prefix sum ⇒ per-material pixel lists (also gives 2×2-quad coherent tiles).
3. `vg_shade` (indirect dispatch per material bin): fetch 3 vertices (attribute stream), interpolate with the barycentrics (analytic derivatives for texture LOD: ddx/ddy from ray differentials), evaluate the material through the **existing material evaluator** used by `helio-pass-gbuffer` (`helio-mats`), write G-buffer (albedo/normal/orm/emissive/velocity) via storage textures. Needs G-buffer textures created with `STORAGE_BINDING` (check/extend in `GBufferPass`).
4. Depth: a tiny fullscreen render pass writes `Depth32Float` from the resolved depth (`frag_depth`, discards non-VG pixels) with depth-test against the classic G-buffer depth so **classic and VG geometry composite correctly** in either order; order in graph = `GBufferPass` (classic, non-VG meshes) → VG cull/raster → VG shade → rest (foliage, decals, deferred light unchanged).
5. Velocity: from previous-frame instance transform (the scene join already carries prev transforms for `gbuffer_velocity`).
6. Other consumers: **shadows** (`helio-pass-shadow` currently renders classic meshes): VG meshes need a shadow path — phase 2 uses the same cull with light views and a depth-only HW raster of the coarser cut (error τ scaled by light distance) writing to the shadow atlas pages; initial milestone keeps a low-LOD classic proxy for shadows (see D5). Depth pre-pass / Hi-Z / SSAO consume the final depth/G-buffer so they Just Work.

## 10. Risks
1. **Crack-free DAG quality** (boundary locking, seams) is the hardest correctness item; mitigated by crack test + conservative error bounds.
2. **wgpu limits**: no mesh shaders, int64 atomics optional, ≥10 storage buffers per stage needed in cull/shade (scene join already requires 13 natively; WebGPU defaults out of scope).
3. **Same-frame dense-tile detection** requires the one-frame-late routing design above; temporal flicker at the threshold ⇒ hysteresis.
4. **Tier 3-RT feasibility** (proxy LOD BLAS cost, experimental API). Treated as optional last phase.
5. **Shadows/other geometry consumers** (depth prepass, planar reflection, portal, water caustics) read classic mesh data; VG meshes need either proxy or VG-aware paths (D5).
6. **Skinned/deforming meshes, voxel/foliage** are out of scope (rigid static meshes only; `SkeletalMeshComponent` stays classic).
7. **Submodule workflow**: all changes are in Helio + a SceneDB-free pin bump in Pulsar-Native; merge dependency-first per `AGENTS.md`.

- **Error metric rework (helio-vg-build, COOK_REVISION 3, `FORMAT_VERSION` 2)**. Replaced the simplifier's own (quadric, density-normalised) estimate with a *measured* error. Every cluster carries reference points sampled on the original surface (level 0: vertices + triangle centroids; later levels: up to 256 per cluster, worst half by measured distance plus an even stride); each group measures the distance of its input clusters' points to its simplified surface (nearest-triangle grid) and the same points follow their nearest simplified triangle into the produced cluster, so the value is always relative to the *original* mesh and never accumulates. `group_error = max(children, 1.4 x max(measured reverse, forward sample-to-input))`, plus the strict-order epsilon; no sums, no 2x blanket margin. ## 13. Known bugs (open)

- **VG-BUG-1: RESOLVED (cost), policy decided.** Tier 3 dense tiles cost 93-229 ms and the RT backend never ran. Measured per kernel (GPU timestamp scopes inside `VgDense`, in every capture JSON): `peel` 31.6 ms + `peel masked` 62.8 ms of the 95.0 ms; binning, compaction, mask union, footprint, collect were all <= 0.3 ms. Cause: Tier 3 *replaced* Tier 1/2 inside dense tiles, so each tile listed every cluster whose bounding sphere touched it (about 2,500 per tile, 478k entries over 193 tiles) for about 41 real opaque / 3,200 masked triangles per tile; one workgroup per tile re-streams the list per layer, so the pass lasted as long as the slowest tile. Fix: Tier 3 now adds only the clusters the cull diverted to the dense bin (about 8 per tile, alpha-masked leaves never enter Tier 3) and `vis_resolve` merges by depth (`FLAG_DENSE_MERGE`): VgDense 95.0 -> 0.96 ms (peel), 0.15 ms (RT), forest frame equal to Tier 2 within noise. Also fixed: mask flicker (latch with decay in `tile_classify`, `dense_age`; est feeds hits too; per-frame cap), opaque/masked cluster lists separated, bin/collect dispatch zeroed when nothing is dense, `make_args`, two redundant `device.poll` calls (1.5 ms CPU each frame -> RT prepare 1.7 ms -> 0.12 ms), alpha-masked clusters no longer gate RT (they are never candidates), `frames_rt` > 0 (283 of 300 settle frames; TLAS rebuilt 6x, reused 292x; RT == peel bit-exact, 0.0135% of pixels differ from Tier 2), Tier 3 engages only when RT is ready (or Tier 2 is the no-int64 tiled fallback) and idles at 0.016 ms. Overflow counter reads 0 (`bin_overflow`). **Remaining**: (1) Tier 3 does not beat Tier 2 on an RTX 4090 at any measured density (up to 9.3 tri/pixel per tile, 40 M selected triangles): no crossover for the peel; RT break-even needs more than about 2.5 tri/pixel over 100+ tiles and is not reached; Tier 3 stays opt-in. (2) RT proxy pages share the 512 MiB pool and are starved at density >= 3 (needs a reserved proxy slot share or a separate pool). (3) The peel still streams per-layer; only the diverted clusters make it cheap. (4) Not measured on a GPU without 64-bit atomics (the case where the peel is meant to engage). (5) Absolute times above were taken while another process used the GPU for part of the runs.
