# Blueprint System Architecture

How a Blueprint goes from the editor graph to code the game runs.

---

## The Pipeline

```
editor graph ──save──▶ graph_save.json
     │
     ▼ Compile (F7)
validation ──▶ blueprint_compiler::compile ──▶ pulsar_script_vm::Module
                                                   │
                         ┌─────────────────────────┴──────────────────────────┐
                         ▼ VM target                                           ▼ Rust target (default)
              events/.build/module.json                       pulsar_script_codegen::actor
              loaded by the ScriptRuntime                     → events/events.rs, vars/mod.rs, mod.rs
```

`graph_save.json` is the source of truth. Everything under `events/` and `vars/` is regenerated on
compile; never edit it by hand.

Plugin paths below are relative to `plugins/vendor/blueprint_editor/` (the Plugin_Blueprints
submodule).

---

## 1. Save — `graph_save.json`

A class is a directory containing `graph_save.json` (`src/io/save_load.rs`), either
`<project>/src/classes/<Name>/` or a `<Name>.class/` folder anywhere in the project
(`src/features/class_dirs.rs`).

The file is a `//` comment header followed by a `graphy_blueprint::BlueprintAsset` as JSON
(`graph/src/lib.rs`): `format_version` (currently 2, see `graph/src/codec.rs`; v1 files are
upgraded on load), `main_graph`, `subgraphs` (alias `local_macros`), `local_events`, `variables`,
`editor_state` and `blueprint_metadata`. A component class also has a `prefab.json` sidecar.

## 2. Validation

`run_validation_stage` in `src/features/compilation/compiler.rs` runs before every compile and
aborts it on errors:

1. The editor graph is converted to a `graphy_blueprint::GraphDescription` and checked for
   dangling connections and empty node types.
2. `blueprint_compiler::authored::expand_graph` lowers it to a `graphy::GraphDescription` and
   inlines local and library macros.
3. `graphy::DataResolver::build` runs data-flow analysis against the `pulsar_std` catalogue
   (`src/std_nodes.rs`, built from `pulsar_std::get_all_nodes()`).

## 3. Compile to a script module — `compiler/` (`blueprint_compiler`)

`blueprint_compiler::compile(&ClassSource, &NativeRegistry)` turns the graph into a
`pulsar_script_vm::Module`. The crate doc in `compiler/src/lib.rs` is the reference; in short:

- **Events** become exported functions: `begin_play`, `on_tick` → `tick(delta_time)`,
  `on_end_play` → `end_play`, `main`, input events, and custom events (`on_<uid>`).
- **Built-in flow nodes** are intrinsics with real jumps (`flow()`): `branch`, the switches,
  `multi_branch`, `sequence`, `for_loop`, `while_loop`, `gate`, `multi_gate`, `flip_flop`,
  `do_once`, `do_n`, `delay`, `retriggerable_delay`. Stateful ones keep per-instance hidden
  variables; delays suspend the call until that much game time has passed.
- **Other control-flow nodes** run their own `pulsar_std` body through a *selector* native
  (`std::<node>` with an `exec_outputs` attribute, generated by `#[blueprint]` in
  `crates/core/pulsar_macros`) that reports which `exec_output!` fired.
- **Other nodes** call `std::<node_type>`; `native::<name>` nodes call any registered native
  (component and value-type methods, accessors). Variables, component property/method nodes and
  engine events (`event::on/send/broadcast/to_class::<Event>`) are covered in the crate doc.

## 4a. VM target

Writes `<class>/events/.build/module.json` (and a `language` file containing `blueprint`).
`pulsar_game::scripting` loads it into `pulsar_script_runtime::ScriptRuntime`
(`ScriptDriver`, `module_file` prefers `module.pvm` over `module.json`), and the `TickLoop` drives
it once the game calls `enable_project_scripting()`.

## 4b. Rust target (default)

`CompileMode` defaults to `DirectRust` (`src/core/types.rs`); the toolbar switches between
"Rust" and "VM". The same module is exported to Rust by
`pulsar_script_codegen::actor::generate_actor`:

- `events/events.rs`: a `#[derive(EngineClass)]` struct holding a
  `pulsar_game::scripting::export::ExportedScript`, with `impl Actor`
- `events/mod.rs`, `<class>/mod.rs`, and `vars/mod.rs` (from `vars_save.json`)
- `pub mod <Name>;` appended to the parent `mod.rs` (normally `src/classes/mod.rs`)

The graph needs at least one event node. Classes with component-scoped event subscriptions are
refused ("Use the VM compile target for this class").

## Class Directory Layout

```
src/classes/<ClassName>/          (or <ClassName>.class/)
├── graph_save.json               ← source of truth
├── prefab.json                   ← component classes only
├── vars_save.json                ← written on variable changes and Rust compile
├── mod.rs                        ← Rust target
├── vars/mod.rs                   ← Rust target
└── events/
    ├── mod.rs                    ← Rust target
    ├── events.rs                 ← Rust target; generated, DO NOT EDIT
    └── .build/
        ├── module.json           ← VM target
        └── language              ← VM target
```

Generated projects get `src/classes/mod.rs` rebuilt from disk (one `pub mod X;` per class
directory with a `mod.rs`) by `ensure_core_bootstrap` in
`crates/core/engine_backend/src/services/core_project_builder.rs`, on Build Core, PIE and packaging.

## Adding Nodes

- A `pulsar_std` node: see `/add-blueprint-node`. Control-flow nodes need no compiler change;
  they run through their selector native.
- A new *intrinsic* (compiler-lowered) flow node: mark it `intrinsic: true` in `pulsar_std` and
  implement it in `flow()` in `compiler/src/lib.rs`.

## Tests

- `cargo test -p blueprint_compiler` (`compiler/tests/compile.rs`, `compiler/tests/authored.rs`)
- `cargo test -p blueprint_editor_plugin --tests` (save formats, the `pulsar_std` catalogue)
- `cargo test -p pulsar_game --lib blueprint_codegen_drift` (exported actors compile against the
  current crates); `cargo test -p pulsar_game --test random_world_blueprint`
